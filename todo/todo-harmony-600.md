# The Harmony 600: what the FHSDK can do for it

Every requirement possible on the Harmony 600, by subject, ticked where a test proves it. The list is generated by
`make requirements-write` from the requirements data and the proofs in the tests, so a box changes with a test and
never by hand; an impossible requirement is left out, and one marked "find out first" is not known to be possible.
An open one says in brackets whose work is missing: the FHSDK, done once for every remote; its family; the remote
itself; or only a run on a unit.
What each requirement means is [the requirements](../docs/remote-requirements.md), and what a box rests on
[the evidence](../docs/remote-requirements-evidence.md).

Open: 47, of which 24 its own or its family's work, 18 the FHSDK's work alone and 5 a run on a unit alone.

## The whole configuration

- [x] R1 Read the configuration off the remote, whole and checked.
- [x] R2 Understand a configuration: its devices, activities, keys, screens, delays and codes, and what each key will send.
- [ ] R3 Read a configuration back into a recipe, so a setup can be edited and rebuilt; from our own builds whole, favourites included, through a record of ours carried inside. (waits on the FHSDK)
- [x] R4 Build a whole configuration from a recipe.
- [x] R5 Write a configuration to the remote, verified by reading it back, and the remote runs it.
- [ ] R6 Write the user's own remote: take a remote never seen, record its identity and a full backup, and from then on write to that unit only. (waits on the FHSDK)
- [x] R7 Refuse a configuration that does not fit the model or would be mishandled, and say what is over.
- [ ] R8 Detect changes made on the remote since the app last wrote it, the help's own delay fixes among them, and keep or discard them. (waits on the FHSDK)

## Devices and codes

- [ ] R10 Add a device from the catalogue with its commands, power and inputs, choosing the code set version where a device has several. (waits on the FHSDK)
- [ ] R11 Add a device the catalogue does not know, from its type and commands taught from its original remote, its definition saying it was learned. (waits on its family)
- [ ] R13 Remove a device, and say and settle what happens to the activities and favourites that used it. (waits on the FHSDK)
- [ ] R14 Set how a device is powered: one key or two, none, always on, kept on between activities, extra commands to power up, a power code that must be held. (waits on the FHSDK)
- [ ] R15 Set how a device changes inputs and which inputs it has. (waits on the FHSDK and its family)
- [ ] R16 Set a device's delays, and put them back to their defaults. (waits on the FHSDK)
- [ ] R17 Set how many times a device's commands repeat. (waits on the FHSDK)
- [ ] R18 Set how a device tunes a channel number. (waits on the FHSDK and its family)
- [ ] R19 Add, fix and remove a device's command, and put a fixed one back to its original code. (waits on the FHSDK)
- [ ] R89 Tune one command of a device: how many times a press sends it, how long a held key waits before it repeats and how fast it then repeats, kept in the document and never replaced by the catalogue's value. (waits on the FHSDK)

## Activities

- [x] R21 Create an activity of a kind with its devices; starting, switching and Off behave as the manuals describe.
- [ ] R22 Say which device does which job in an activity, and map its keys from that, a learned command with a standard name landing on its usual key. (waits on its family)
- [x] R23 Set each device's input in an activity, or leave it alone.
- [ ] R24 Include a pass through device in an activity. (waits on a run on a unit)
- [ ] R26 Remove an activity. (waits on the FHSDK)
- [ ] R27 Give an activity an icon. (find out first)
- [ ] R28 Order the activity menu and an activity's device list. (waits on its family)
- [x] R29 Choose which activities the activity keys start.
- [ ] R30 Add steps to an activity's start and end: commands, pauses, a sequence. (waits on the FHSDK)
- [ ] R90 Choose the order in which an activity switches its devices on and off. (waits on the FHSDK and its family)
- [ ] R91 Choose the screen an activity opens on, where the remote has more than one. (find out first)

## Keys and screens

- [ ] R31 Change what a key does in an activity: any command of its devices, a sequence, or nothing. (waits on the FHSDK)
- [ ] R32 Change what a key does for a device in device mode, any device's command included, such as the receiver's volume in TV mode. (waits on the FHSDK)
- [ ] R33 Give a device its device mode map from the catalogue, every key and screen page, as Logitech's software would. (waits on its family)
- [ ] R34 Put commands on an activity's screen, labelled and ordered, across pages. (waits on a run on a unit)
- [ ] R35 Put commands on a device's screen pages in device mode. (waits on the FHSDK)
- [ ] R36 A screen button that opens a page of the user's own commands, and a button back. (waits on the FHSDK)
- [x] R37 Make a named sequence with pauses and put it on a key or the screen, within what the remote survives.
- [ ] R41 Show every screen as the remote will draw it, before writing. (waits on the remote itself)
- [ ] R42 Choose the look of the screens: typeface, inks, colours, icons, background, theme, choices per screen. (waits on its family)
- [x] R43 Draw the remote's face and know which key is which.
- [ ] R44 Give every activity the remote's own help, the advanced help and its delay fixing included. (waits on its family)

## Favourites

## Settings

- [ ] R48 How long the screen stays lit, and its brightness. (waits on the remote itself)
- [ ] R49 The motion sensor on or off. (waits on a run on a unit)
- [ ] R50 The Remote Assistant and the "Starting Activity" message on or off. (waits on its family)
- [ ] R51 The kind of help, Smart or Full. (find out first)
- [ ] R52 The clock: the right time, how it is shown, and read back. (waits on its family)
- [ ] R53 A slideshow of the user's pictures. (find out first)

## Learning

- [ ] R54 Learn an infrared command from the original remote through the Harmony's own receiver. (waits on its family)
- [ ] R55 Use a learned code in a device, on any key or screen button, input commands included. (waits on its family)
- [ ] R56 Recognise a learned code as a known kind and keep it compactly, or as captured when it is not. (waits on its family)

## Backup and restore

- [x] R58 Back up a remote whole and keep it on the computer.
- [x] R59 Put a backup back on the same remote.
- [x] R61 Clear a remote's setup so it starts fresh, by writing an empty configuration, never through the firmware's own reset.

## Status and identity

- [ ] R62 Find the attached remotes and their models without claiming them. (waits on a run on a unit)
- [x] R63 Tell one unit from another, and say when the wrong one is connected.
- [x] R64 The firmware version and hardware details.
- [ ] R65 The battery level, and a warning or refusal before a write when it is low. (waits on the FHSDK and the remote itself)
- [ ] R66 Progress during a read or a write, and the remote showing it is being written. (waits on its family)
- [ ] R67 Show live which key is pressed on a connected remote. (waits on a run on a unit)

## Firmware

- [ ] R69 Know the firmware state: running, safe mode or bootloader, and whether a newer version exists. (waits on the FHSDK and the remote itself)
- [ ] R70 Install Logitech's own unmodified firmware, from a file the user has or from Logitech's update service; the 600, 650 and 700 only, by decision 18. (waits on the remote itself)
- [ ] R71 Bring a stuck remote back. (waits on the remote itself)

## Logitech's service

- [ ] R72 Import devices and activities from the user's own Logitech account, if they ask and give their own credentials; the app works the same without it. (waits on the FHSDK)

## An existing setup

- [ ] R83 Take over a configuration Logitech's software built as a recipe that rebuilds to the same behaviour, so an existing setup is not entered again. (waits on the FHSDK)
